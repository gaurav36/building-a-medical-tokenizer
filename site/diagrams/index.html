Companion diagrams / medtok

From corpus to token IDs.

Three boundaries to keep distinct: learning a vocabulary, evaluating it, and connecting it to a model.

01 / The tokenizer pipeline

Training learns. Encoding applies.

  1. TRAINING INPUTPrepared medical documents

    Deduplicate and split. Only training documents supply the pair frequencies.

  2. TRAINING OUTPUTVocabulary + ranked merges

    ByteLevel pre-tokenization, a 256-byte alphabet, and BPE with a 16k target.

  3. ENCODING INPUTPreviously unseen text

    Use the frozen pre-tokenizer and learned merges. No new vocabulary is learned.

  4. ENCODING OUTPUTPieces mapped to IDs

    The byte-level decoder reconstructs text from the complete ID sequence.

Textpre-tokenize → apply BPE → IDs → decode

Byte-level display symbols are not literal additions to the input. Offsets describe spans; trimming offsets is not the same as removing whitespace from decoded text.

03 / The model contract

A token ID is an embedding address.

PRETRAINED PATH

Original tokenizer

Original IDs → learned embedding rows → existing model. Keep this contract for ordinary fine-tuning.

NEW VOCABULARY PATH

Custom tokenizer

New IDs → compatible learned embeddings → a model trained or deliberately adapted for those IDs.

Resizing is not remapping.

Adding enough embedding rows changes a matrix's shape. It does not teach those rows what your new pieces mean.
